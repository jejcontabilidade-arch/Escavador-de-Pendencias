## 🏗️ Planejamento & Arquitetura

### 🎙️ Arquitetura de Voz e NLP (WhatsApp)
A captação de mensagens de voz é executada na camada do gateway Node.js (`whatsapp-web.js`), que detecta mídias dos tipos de áudio e as baixa nativamente. Para manter o gateway leve e centralizar a segurança e chaves de API, os bytes do áudio são repassados ao Flask em Base64.
No backend Python, a transcrição é feita de forma desacoplada chamando a API Whisper da OpenAI (`whisper-1`) em português. O texto retornado atualiza a variável principal da mensagem, permitindo que todo o ecossistema NLP preexistente (GPT-4o-mini e heurísticas locais) interprete o comando de voz exatamente como se fosse um texto digitado.

### 📊 Consolidação de Dados sob Demanda
Anteriormente, as planilhas consolidadas eram atualizadas apenas ao término da execução completa dos robôs. Desenvolvemos uma arquitetura de consolidação sob demanda: as funções em `rebuild_utils.py` lêem os arquivos físicos locais de status (`status.json` e `status_nota_fiscal_xml.json`) e os arquivos baixados para reconstruir as planilhas premium em tempo de execução. Isso permitiu integrar a reconstrução tanto no webhook do WhatsApp (enviando a planilha atualizada na hora) quanto no clique de download do painel web.

```python
# Gravar dados decodificados
audio_bytes = base64.b64decode(audio_obj.get("data"))
with open(temp_audio_path, "wb") as f_audio:
    f_audio.write(audio_bytes)

# Enviar para a API OpenAI Whisper
url_whisper = "https://api.openai.com/v1/audio/transcriptions"
headers_whisper = {"Authorization": f"Bearer {openai_key}"}

with open(temp_audio_path, "rb") as f_file:
    files = {"file": (temp_filename, f_file, mimetype)}
    data = {"model": "whisper-1", "language": "pt"}
    resp = requests.post(url_whisper, headers=headers_whisper, files=files, data=data, timeout=30)
```
Se a transcrição retornar sucesso, o robô envia um feedback imediato no chat:
`🎙️ *[Comando de Voz Compreendido]:* "texto"`
E prossegue para a execução.
